Power Latch Circuit (Hardware Power Switch)

Power latch circuit for a true hardware power-off state, powered directly from VBAT (not from the regulator's own output, avoiding the chicken-and-egg problem where the "off" control depends on power that no longer exists once off).

Reference: Latching Power Switch Circuit (Auto Power Off Circuit) for ESP32, ESP8266, Arduino — RandomNerdTutorials

Core Topology

  • P-channel MOSFET as high-side switch: Source → VBAT, Drain → TPS63031's EN pin
  • Pull-up resistor from gate to VBAT — default state is OFF (gate high = same as source)
  • Power button: one leg to GND, other to the gate node — pressing pulls gate down, turns PMOS ON, powers everything up
  • ESP32 GPIO (once booted) taps the same gate node — firmware pulls it low to latch/hold power on after the button's released
  • Shutdown: firmware releases/drives that GPIO high, pull-up brings gate back up, PMOS turns off, whole board (including the ESP32 itself) loses power cleanly
  • Optional safety feature: RC-timed "force off" on a long press, so a crashed/hung firmware can't prevent the device from being physically powered down

Things to Think About / Still Open

  • This does NOT cut off literally everything. Residual draw sources even in the "off" state:
    • TPS63031's own shutdown-mode leakage (0.1–0.9µA per datasheet) — only relevant if this circuit gates EN rather than physically cutting VIN/VINA.
    • Battery Voltage Sense divider (100k/100k) is wired directly across VBAT, independent of this switch — will keep drawing ~21µA continuously even when "off," unless it's specifically re-routed to be powered downstream of the same PMOS switch.
    • The latch circuit's own pull-up resistor leakage — kept negligible with a large enough resistor value (100kΩ+).
  • Decision needed: is ~20-25µA total residual draw in the "off" state acceptable (roughly 15-18mAh lost per month of storage — a small fraction of the 3450mAh capacity), or worth eliminating by routing the voltage divider through the same switch? If eliminated, only the regulator's own sub-1µA shutdown leakage remains.
  • PMOS part selection — needs to handle the ESP32's active current (~73mA) comfortably. A small, cheap, common part like an AO3401 is likely comfortable overkill margin-wise, but should be confirmed once the exact circuit is finalized.
  • GPIO-to-gate-node protection — the reference circuit and its community comments discuss needing some protection (diode or resistor) between the ESP32 GPIO and the shared gate node, so the GPIO isn't directly shorted to GND whenever the button is pressed simultaneously. Worth reading the article's comment section for real-world gotchas others have hit.
